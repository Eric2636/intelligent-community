# 微信小程序新功能与体验优化设计

日期：2026-07-26  
状态：已与需求方逐项确认并完成书面复核  
涉及项目：

- `intelligent-community`：微信小程序
- `intelligent-community-admin`：后端接口
- `intelligent-community-admin-web`：后台管理系统

## 1. 目标

本轮工作分四批完成：

1. 修复用户资料、权限交互、游客查询和页面返回问题，并彻底下线小区跑腿。
2. 统一列表展示，改造小程序热搜索，优化后台键盘操作和意见反馈。
3. 建立可实际使用的站内消息通知闭环。
4. 建立覆盖小程序和后台接口的访问日志与接口管理能力。

每批都需要同步更新功能清单、接口说明、数据库变化和测试清单。

## 2. 分支与环境规则

- 三个项目的业务代码、配置、测试和项目文档只允许在各自的 `dev` 分支修改。
- 开始修改前必须检查当前分支和未提交改动，不得直接在 `test`、`master`、`main` 或生产分支编写业务代码。
- 每一批独立开发、验证和提交，避免不同批次混在同一个提交中。
- 数据库变化必须通过迁移文件完成，不得手工直接修改测试或生产数据库。
- `dev` 完成并验证后，合并或挑选已批准的提交到 `test`；测试环境只能从 `test` 分支发布。
- 测试通过后，再将批准的 `dev` 变更合入生产分支；不得将 `test` 合入生产分支。
- 小程序开发版使用测试接口；体验版从 `test` 上传并连接测试接口；审核和线上版本只从生产分支上传并连接生产接口。
- 后端和后台管理系统的测试环境只能从本地 `test` 分支部署，生产环境只能从本地生产分支部署。
- 开发、测试和生产使用各自的环境配置、数据库及微信配置，测试数据不得进入生产环境。
- 本设计不授权提交、推送、合并、上传小程序或部署；这些动作需要单独确认。

## 3. 统一界面原则

- 新增或调整的弹框、按钮、输入框、列表、空状态、标签、加载状态和滑动操作优先采用 TDesign 组件及视觉规范。
- 仅在 TDesign 无法满足时增加少量自定义样式。
- 自定义样式必须沿用项目现有颜色、字号、间距、圆角和交互反馈。

## 4. 第一批：核心缺陷修复与跑腿下线

### 4.1 用户名、头像与默认头像

- 用户资料表是用户名、头像和身份信息的真实来源。
- 业主互助的发布、列表和详情接口必须返回发布者头像，列表和详情均展示头像。
- 用户修改用户名或头像时，后端在同一次事务中同步更新该用户所有历史内容中的展示快照，包括：
  - 业主互助任务及相关参与者展示信息；
  - 论坛帖子、回复及评论关联展示信息；
  - 小区市场商品、评论、订单关联展示信息；
  - 其他保存了该用户用户名或头像快照的记录。
- 同步不得覆盖后台发布标签或用户身份标签。
- 任一历史数据同步失败时，用户资料修改整体回滚，避免各模块显示不一致。
- 设置一张统一的系统默认头像。后端序列化时为空则返回默认头像，小程序组件渲染时再次兜底。
- 新数据和历史数据都不得显示空白头像。

### 4.2 权限登录弹框

- 建立统一的 TDesign 风格授权弹框，包含“授权登录”和“取消”。
- 所有需要登录的新增、修改、删除或个人数据操作统一使用该弹框，不再跳转“我的”页面。
- 登录成功且身份选择完成后关闭弹框并停留在当前页面，不自动继续原操作。
- 用户需要再次点击原按钮，才执行该操作。
- 点击取消只关闭弹框，不跳转、不执行操作。
- 已登录但尚未选择身份时，只引导身份选择。
- 防止连续点击导致多个弹框或重复登录请求。

### 4.3 小区市场游客查询

未登录用户允许：

- 查询商品分类、商品列表和商品详情；
- 使用热搜索、筛选和排序；
- 查看商品评论；
- 查看卖家主动公开的信息。

以下操作仍需登录：

- 收藏、评论和发布商品；
- 下单及其他订单状态修改；
- 查询个人收藏、个人商品和个人订单。

公开读取接口使用可选登录态。空 Token、失效 Token 或无 Token 不得导致公开查询失败；登录态只用于补充“是否已收藏”等个性化字段。

### 4.4 “我的任务”返回修复

- “我发布的、我领取的、草稿、已取消”等页签切换只改变当前页面状态和数据，不新增页面历史。
- 无论连续切换页签多少次，点击一次返回都回到“我的”页面。
- 防止连续点击“我的任务”入口重复压入相同页面。

### 4.5 彻底删除小区跑腿

项目尚未上线，因此彻底下线小区跑腿：

- 删除小程序底部导航、页面入口、页面分包、接口封装、跑腿专用组件和资源。
- 删除后端跑腿路由、服务、数据传输对象和仅供跑腿使用的代码。
- 删除后台管理系统中的跑腿入口和管理能力。
- 使用数据库迁移删除跑腿专用数据表、索引和外键，不保留跑腿历史数据。
- 删除前检查上传、用户、通知等共享能力，只移除跑腿专属代码。
- 删除后旧跑腿路径给出“功能已下线”或安全回退，不允许白屏或启动失败。

## 5. 第二批：列表、搜索和常用页面优化

### 5.1 列表文字和宽度

- 检查微信小程序所有业务列表。
- 标题最多显示 1 行，正文或描述最多显示 3 行，超出显示省略号。
- 没有独立标题的任务描述最多显示 3 行。
- 限制文字容器宽度，头像、身份标签、时间和操作区域不得被挤压。
- 详情页正文保持完整展示，不应用列表截断规则。

### 5.2 微信小程序 RxJS 热搜索

- 微信小程序内所有仍保留的搜索框统一改为 RxJS 输入流。
- 用户停止输入 500 毫秒后自动查询。
- 关键词去除首尾空格后为空时，不发送关键词搜索请求，恢复默认列表。
- 与上一次有效关键词相同时不重复查询。
- 新输入产生后取消旧查询，或忽略旧查询的迟到结果，避免旧结果覆盖新结果。
- 删除小程序搜索按钮，保留 TDesign 搜索图标、输入框和清空能力。
- 页面隐藏或卸载时取消订阅，避免重复监听和内存泄漏。
- 只引入 RxJS 所需模块，控制小程序主包和分包体积。

### 5.3 后台键盘操作

- 后台管理系统不改为热搜索。
- 所有后台搜索输入框支持 Enter 查询，并保留现有搜索按钮。
- 登录页用户名或密码输入框按 Enter 可以登录。
- 查询或登录处于加载状态时禁止重复提交。

### 5.4 “更多服务”和意见反馈

- “更多服务”只保留“消息通知”和“意见反馈”。
- 意见反馈页只保留多行反馈内容输入框和提交按钮。
- 删除现有反馈类型和联系方式字段。
- 去除首尾空格后内容为空时禁止提交。
- 意见反馈属于需要登录的新增操作。
- 未登录点击提交时显示统一授权弹框；登录后不自动提交，用户需要再次点击提交。
- 当前实际意见反馈功能没有图片上传；功能清单中“反馈图片上传”的过期描述需要纠正。

## 6. 第三批：消息通知

### 6.1 第一阶段通知事件

论坛：

- 有人回复我的帖子；
- 有人回复我的评论。

业主互助：

- 有人领取我发布的任务；
- 领取人放弃；
- 领取人提交完成；
- 发布者确认完成或驳回；
- 任务取消及其他需要相关双方知晓的状态变化。

小区市场：

- 有人下单；
- 订单取消；
- 需要买卖双方知晓的订单状态变化。

系统：

- 后台发布的重要公告或系统通知。

本阶段不发送点赞和收藏通知。系统不得给操作人自己发送通知；同一个业务事件通过唯一去重键只生成一次。

### 6.2 数据与一致性

- 通知保存类型、接收人、触发人、关联业务类型和编号、标题、摘要、已读时间、软删除时间、去重键和创建时间。
- 通知只保存展示所需摘要，不复制完整帖子、任务或订单。
- 业务状态变化和通知创建在同一个数据库事务中完成；通知创建失败时业务状态变化回滚。
- 业务内容后来被删除时，通知仍可保留；点击后提示“内容已不存在”。

### 6.3 消息中心交互

- “我的”页面及现有通知入口展示未读数量。
- 通知列表按时间倒序，明确区分已读和未读。
- 点击通知后标记已读，并跳转到对应帖子、任务或订单详情。
- 支持“一键全部已读”。
- 使用 TDesign 风格滑动单元格；向左滑动露出红色“删除”按钮，交互参考 iOS 微信列表。
- 删除采用用户侧软删除，立即从当前用户列表消失，不影响业务数据或其他用户。
- 进入消息页、读取、全部已读或删除后立即刷新未读角标。
- 小程序重新进入前台时重新获取未读数量。
- 重复请求不得造成通知重复、未读数负数或重复累计。

## 7. 第四批：全接口访问日志与接口管理

### 7.1 接口管理

- 以“请求方式 + 标准化路由”唯一识别接口，例如 `GET /api/tasks/:id`。
- 动态编号必须归一为标准路由，不能按每个实际编号生成接口项。
- 接口列表展示来源、请求方式、标准路径、管理员描述、日志开关和更新时间。
- 新接口首次注册或随版本启动时自动进入接口列表，日志默认开启。
- 只有超级管理员可以查看接口列表、修改描述和切换日志开关。
- 关闭接口日志后不再记录该接口的普通访问日志，但 500 级异常仍写入独立错误日志。
- 接口描述和开关变更写入现有后台操作日志，记录操作者和时间。

### 7.2 访问日志

统一后端中间层覆盖微信小程序和后台管理接口。记录：

- 调用来源；
- 请求方式；
- 标准路由和实际路径；
- 真实客户端 IP；
- 已登录用户或管理员标识；
- HTTP 状态和业务状态；
- 请求耗时；
- 调用时间；
- 脱敏后的错误摘要。

不得保存：

- 密码、Token、Cookie 和微信授权凭证；
- 完整请求头；
- 上传文件内容；
- 未脱敏的手机号等敏感查询参数；
- 可暴露密钥或内部实现的完整异常堆栈。

真实 IP 仅从服务器明确信任的反向代理链中获取，防止客户端伪造转发头。

### 7.3 写入与故障隔离

- 访问日志由统一中间层在请求结束阶段生成，接口业务代码不重复手工记录。
- 正常返回、业务失败和系统异常都进入统一流程。
- 日志写入失败不得改变原接口业务响应，但服务器必须留下日志系统故障记录。
- 上传等耗时接口只记录请求元数据、结果和耗时，不记录文件内容。
- 接口关闭普通日志后，500 级错误仍进入独立错误日志。

### 7.4 后台筛选与权限

- 访问日志、错误日志和接口管理仅超级管理员可用。
- 支持按 IP、接口、请求方式、来源、精确状态码或状态类别、调用时间范围、用户或管理员、耗时筛选。
- 默认按调用时间倒序分页。
- 支持 Enter 查询、重置条件和导出当前筛选结果。
- 错误详情只展示脱敏摘要。

### 7.5 保存周期

- 普通访问日志保留 90 天。
- 定时任务分批清理超过 90 天的数据，避免大事务影响在线请求。
- 为调用时间、IP、接口、状态等常用筛选字段建立索引。
- 接口配置和后台操作日志不随普通访问日志清理。
- 清理任务的执行结果写入运维记录。

## 8. 异常处理

- 用户资料与历史展示信息同步采用事务，失败时整体回滚。
- 权限弹框和登录请求防重复触发。
- 热搜索只接收最新关键词的结果；失败时保留当前内容并提示重试。
- 消息业务变更和通知创建保持事务一致性。
- 访问日志故障不得拖垮主业务，但必须可被运维发现。
- 公开读取接口能够容忍未登录、空 Token 和失效 Token。
- 跑腿删除后不存在残留导航、无效分包、构建错误或数据库外键错误。

## 9. 测试与验收

### 9.1 自动测试

后端重点覆盖：

- 用户资料修改与全部历史展示信息同步、事务回滚；
- 默认头像序列化；
- 小区市场公开查询与登录后个性化查询；
- 通知创建、去重、已读、全部已读和软删除；
- 接口自动注册、默认开启、日志开关和 500 异常强制记录；
- 日志筛选、权限和 90 天分批清理；
- 跑腿数据库迁移及其他模块回归。

小程序重点覆盖：

- 授权弹框、取消、登录后不自动继续和二次点击；
- “我的任务”多次切换后一次返回；
- 列表标题 1 行和正文 3 行；
- 热搜索的空白不搜、500 毫秒防抖、重复不搜和最新结果优先；
- 消息未读角标、已读、跳转、一键全部已读和左滑软删除；
- 意见反馈登录限制、空内容校验和提交状态。

后台管理重点覆盖：

- 搜索 Enter 查询和登录 Enter 提交；
- 普通管理员无日志权限；
- 超级管理员编辑接口描述和日志开关；
- 多条件日志筛选和导出。

### 9.2 每批验证

- 每批在 `dev` 完成构建、静态检查、相关自动测试和本地人工检查。
- 经单独批准后再进入 `test` 分支和测试环境。
- 数据库迁移先在测试数据库验证升级过程和应用启动。
- 测试环境通过后，才能按批准的发布流程进入生产分支。
- 删除跑腿后必须全量检查小程序启动、分包加载、底部导航、后端构建、数据库迁移和其他业务接口。

### 9.3 完成标准

- 不存在空白头像，用户改名或换头像后所有历史内容显示一致。
- 需要权限的操作使用弹框，登录后必须再次点击原操作。
- 小区市场公开查询在未登录状态正常工作。
- “我的任务”切换任意次数后一次返回。
- 所有小程序列表遵守标题 1 行、正文 3 行规则。
- 小程序热搜索满足空白不搜、500 毫秒防抖、重复不搜。
- 意见反馈页面只保留内容输入框和提交按钮，并要求登录。
- 消息能够生成、查看、已读、跳转、全部已读和左滑软删除。
- 接口可以配置是否记录普通日志，500 异常始终保留，日志可按确认的条件筛选。
- 小区跑腿代码和数据库表彻底删除，其他模块正常。
- 功能清单、接口文档、迁移说明和自测清单与实际行为一致。
