# 头像内容安全审核设计

日期：2026-07-31

## 目标

修复微信审核指出的“头像发布未接入内容安全 API”问题。微信头像和自定义头像使用同一条后端审核链路；新头像只有在微信内容安全 2.0 返回 `pass` 后才写入用户资料并同步历史作者头像。`risky`、`review`、接口错误或超时均不得让新头像对外展示。

本阶段只处理头像，不扩展论坛、任务、市场等其他 UGC。实现应抽出可复用的微信内容安全客户端，方便后续覆盖其他发布场景。

## 当前问题

- 两个头像入口最终都调用 `uploadLocalFilesToCloud(..., 'avatar/profile/img')`。
- `/api/upload/media` 将文件直接写入 COS，只验证文件类型和大小，不调用微信内容安全接口。
- `/api/user/me` 接受客户端提交的任意图片 URL，可绕过上传入口直接修改头像。
- 微信登录 DTO 仍接受客户端提供的 `avatarUrl`，虽然当前小程序不发送该字段，但它也是潜在绕过入口。
- 当前没有保存异步审核任务，也没有接收微信 `media_check` 回调的公开接口。

## 采用方案

使用微信官方内容安全 2.0 `mediaCheckAsync`：

- `media_type=2`，表示图片。
- `version=2`。
- `scene=1`，表示用户资料。
- `openid` 使用当前登录用户的 OpenID。
- `media_url` 使用已上传到 COS、微信检测服务器可直接下载的 HTTPS URL。

官方说明异步结果会在 30 分钟内推送到消息接收服务器。因此新头像不能在上传完成时立即生效，也不能把“已提交检测”等同于“审核通过”。

不采用 1.0 同步 `imgSecCheck`，因为官方已经停止更新 1.0 接口。也不采用客户端调用，避免暴露 AppSecret 和被绕过。

## 数据模型

后端新增 `AvatarReview`：

- `id`：审核记录编号。
- `userId`：所属用户。
- `mediaUrl`：待审核 COS 地址。
- `traceId`：微信异步任务编号，唯一且可为空。
- `status`：`SUBMITTING`、`PENDING`、`PASSED`、`REJECTED`、`FAILED`、`SUPERSEDED`。
- `suggest`、`label`、`wechatErrcode`：保存微信结果，后台日志使用；不得把敏感分类直接展示给用户。
- `createdAt`、`updatedAt`、`completedAt`。

同一用户只能有一条当前待审核头像。新任务成功提交后，较早的 `SUBMITTING`/`PENDING` 记录标记为 `SUPERSEDED`。旧任务随后回调时只记录结果，不得覆盖较新的头像。

## 后端流程

### 上传与提交审核

1. 已登录用户通过 `/api/upload/media` 上传 `module=avatar&type=img`。
2. 后端将文件写入 COS，得到公网 HTTPS URL。
3. 后端创建 `SUBMITTING` 审核记录并调用微信 `mediaCheckAsync`。
4. 微信接受任务后保存 `trace_id`，将本记录改为 `PENDING`，并把该用户更早的未完成记录改为 `SUPERSEDED`。
5. 接口返回图片 URL、审核记录编号和 `PENDING`，但不修改 `User.avatar`。
6. 微信接口不可用、Access Token 获取失败或未返回 `trace_id` 时，将记录改为 `FAILED`，新头像不生效，并向小程序返回“头像安全检测暂不可用，请稍后重试”。

### 消息回调

新增公开回调地址 `/api/wechat/content-security/callback`：

- GET：校验 `signature`、`timestamp`、`nonce` 后原样返回 `echostr`，用于微信公众平台服务器配置。
- POST：先校验签名和 `appid`，再解析 JSON 回调；不合法请求返回 401/403，且不能改变审核状态。
- 通过 `trace_id` 查找审核记录；重复回调必须幂等。
- `pass`：仅当记录仍为该用户最新的 `PENDING` 记录时，事务内改为 `PASSED`，调用现有用户资料同步服务写入 `User.avatar` 并同步任务、论坛、市场历史头像快照。
- `risky` 或 `review`：改为 `REJECTED`，保留旧头像。
- 回调错误码非 0：改为 `FAILED`，保留旧头像。
- 已 `SUPERSEDED` 的记录不得应用头像。

回调使用独立环境变量 `WX_MESSAGE_TOKEN` 验证签名。生产环境未配置该变量时服务启动失败，避免部署出一个接受任意伪造回调的入口。公众平台消息推送使用明文 JSON 模式；本阶段不实现加密消息模式。

### 防绕过

- `/api/user/me` 不再允许把头像改成与当前头像不同的 URL；头像变更只能来自审核回调。
- 小程序保存其他个人资料时不再提交 `avatar` 字段。
- 微信登录接口不再使用客户端传入的 `avatarUrl` 更新数据库。
- 默认头像和数据库中已经生效的旧头像不重复送审。

### 状态查询

新增 `GET /api/user/avatar-reviews/:id`：

- 仅记录所属用户可访问。
- 返回 `PENDING`、`PASSED`、`REJECTED` 或 `FAILED` 以及通用提示。
- 不向用户返回微信命中标签、关键词或内部错误详情。

## 小程序交互

1. 微信头像和自定义头像继续共用 `uploadAvatar`。
2. 上传成功后不立即替换正式头像，保存审核记录编号到本地，并显示“头像审核中，通过后自动生效”。
3. 头像页短时轮询审核状态；离开页面后停止轮询。再次进入个人资料页时根据本地审核编号查询一次。
4. `PASSED`：重新获取个人资料，展示新头像，提示“头像已更新”，清除本地审核编号。
5. `REJECTED`：保留旧头像，提示“头像含违规信息，请重新选择”，清除本地审核编号。
6. `FAILED`：保留旧头像，提示“头像审核失败，请重新选择”，清除本地审核编号。
7. 超过短时轮询窗口仍为 `PENDING` 时只提示“头像仍在审核中”，不阻止用户保存姓名、性别等其他资料。

违规提示只说明所选头像不可用，不展示政治、色情等具体标签，符合本次微信修改指引。

## 测试

后端自动测试覆盖：

- 提交审核时参数固定为资料场景、图片和 2.0。
- 微信任务提交失败时头像不生效。
- 回调签名错误、AppID 错误和未知 `trace_id` 不修改数据。
- `pass` 回调更新当前头像并同步历史快照。
- `risky`、`review` 和微信错误保留旧头像。
- 重复回调幂等。
- 较旧任务晚到的 `pass` 不能覆盖较新的任务。
- 客户端直接 PATCH 新头像 URL 被拒绝。
- 登录接口不能通过 `avatarUrl` 绕过审核。

小程序自动测试覆盖：

- 两个头像入口都调用同一个上传审核流程。
- 上传后显示审核中而不是立即替换正式头像。
- `PASSED` 刷新用户资料；`REJECTED`/`FAILED` 显示通用提示。
- 保存个人资料的 payload 不包含头像字段。
- 页面卸载后停止轮询。

## 发布与配置

1. 在 `dev` 完成数据库迁移、代码和测试。
2. 合入 `test`，备份测试数据库、执行迁移并验证微信回调。
3. 为生产后端配置 `WX_MESSAGE_TOKEN`，备份生产数据库，部署生产分支并执行迁移。
4. 在微信公众平台配置生产消息接收地址、相同的 `WX_MESSAGE_TOKEN` 和明文 JSON 模式。
5. 验证生产回调 URL、伪造签名拒绝、头像上传 `PENDING` 和真实回调。
6. 将小程序变更合入生产分支，由用户使用微信开发者工具上传并重新提交审核。

若公众平台无法配置 JSON 明文回调，停止上线并补充对应的 XML 或加密消息适配，不能降低签名校验要求。
