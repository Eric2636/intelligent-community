# 统一用户标签设计

## 目标

让后台“用户管理”成为全系统唯一的有效用户标签来源。同一用户在小程序和后台的所有展示位置始终显示相同标签，且不再受内容发布入口或历史内容标签快照影响。

## 有效用户标签

有效用户标签按当前数据实时计算：

1. 用户存在启用中的管理员绑定时，显示管理员身份标签：第三方管理员显示所属单位；超级管理员显示“平台管理员”；官方普通管理员显示“网站管理员”。
2. 没有启用中的管理员绑定时，显示 `User.identityType` 对应的默认标签：“业主”或“小区外人员”。
3. 两者均不存在时，不显示过期标签；需要身份的写操作沿用现有身份选择流程，要求用户选择默认身份。

管理员解绑、停用、所属单位变更，以及用户默认身份变更后，重新查询即可获得新标签。

## 数据边界

保留用户事实和审计事实：

- `User.identityType` 保存用户默认身份。
- `AdminUser.boundUserId`、`role`、`orgName`、`enabled` 保存当前管理员绑定与管理员身份。
- 内容的 `createdByAdminId` 保留作操作审计。

不再将最终展示标签作为内容快照读写。现有 `Task.publisherIdentity`、`Task.adminLabel`、`ForumPost.authorIdentity`、`ForumPost.adminLabel`、`ForumReply.authorIdentity`、`MallItem.adminLabel` 将停止参与展示和新内容写入。为降低生产发布风险，本次不直接删除这些历史列；在测试环境验证后，再单独确认是否执行不可逆的列删除迁移。

## 展示与接口

后端统一为内容作者或发布者批量解析有效用户标签，并向任务、留言、回复、市场商品、意见反馈和用户管理接口返回同一 `userTagLabel` / `userTagType`。

小程序只渲染统一字段，不再组合 `contentTagLabel`、`adminLabel`、`publisherIdentityLabel` 或 `authorIdentityLabel`。后台用户管理保留当前“用户标签”列的外观，但数据来自统一解析结果。

## 非范围

后台发布权限不调整：本次不改变普通管理员或超级管理员是否必须绑定小程序用户才可以发布内容的现有规则。

## 验收

- 同一用户在任务、留言、回复、市场商品、反馈和用户管理中显示同一有效标签。
- 用户绑定管理员后，所有位置切换为管理员身份标签；解绑或停用后全部恢复默认标签。
- 用户默认身份变更后，所有未绑定管理员状态下的历史内容立即显示新身份。
- 任何内容发布入口均不再写入或决定展示标签。
