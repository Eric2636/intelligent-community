# 小区市场联系方式弹窗设计

## 目标

将商品详情页的“联系商家”从单条自由文本，升级为由用户主动查看并逐项复制微信号或手机号的底部弹窗。

## 范围

- 修改微信小程序商品发布、编辑与详情页面。
- 修改后端商品 DTO、序列化、商品写入逻辑与 Prisma 数据库结构。
- 修改后台管理系统的小区市场商品编辑与详情展示。
- 不修改评论、消息通知、订单与支付功能。

## 交互

1. 发布和编辑商品时分别填写“微信号”“手机号”，两项中至少填写一项。
2. 商品详情的正文卡片不再直接展示联系方式，避免联系方式在页面首屏长期暴露。
3. 商品详情始终展示“联系商家”按钮；点击时：
   - 没有任何联系方式时，提示“暂无商家联系方式”。
   - 有联系方式时，打开 TDesign 底部弹窗。
4. 弹窗按类型逐项显示“微信号”“手机号”，每项均有独立的复制按钮。
5. 用户点击对应复制按钮后才复制，复制成功关闭弹窗并提示“已复制”；不调用拨号或添加微信能力。
6. 点击遮罩或关闭按钮关闭弹窗。

## 数据与权限

- `mall_items` 新增可空字段 `wechatContact`、`phoneContact`。
- 历史 `contact` 字段保留只读兼容：新字段都为空且旧值有效时，详情弹窗以“联系方式”展示；不自动推断其类型。
- 新商品只写结构化字段；结构化字段被保存后清空旧 `contact` 值。
- 商品归属不影响“联系商家”按钮的显示；商品发布者点击后同样按联系方式值展示或提示。

## 异常处理

- 只对空白值和“保密”视为无联系方式。
- 手机号只接受中国大陆 11 位手机号；微信号仅校验去除首尾空格后的非空长度。
- 不再因联系方式像手机号而调用 `wx.makePhoneCall`，避免越过用户确认。

## 验收

- 同时填写微信号和手机号：详情弹窗显示两项，任一复制按钮只复制对应值。
- 新建商品未填写两项联系方式：前后端均阻止提交并提示。
- 历史单条联系方式：仍能在详情弹窗以“联系方式”展示与复制。
- 空联系方式或“保密”：不打开弹窗，显示“暂无商家联系方式”。
- 商品详情正文不再出现“联系：”。
- 原有评论、收藏、导航、分享与商品管理操作不受影响。
# 补充：手机号也是微信号

当发布者的手机号可直接用于添加微信时，使用 `phoneIsWechat` 布尔字段保存该声明。详情只展示一条“手机号（可添加微信）”并提供一次复制，不复制为微信号和手机号两条相同号码。
