# 消息通知事件清单

最后更新：2026-07-26

## 通用规则

- 业务状态变更和通知创建使用同一个 Prisma 事务；通知写入失败时业务变更回滚。
- `notify` 在 `actorId === recipientId` 时抑制自通知；所有业务通知都有接收人维度唯一约束 `@@unique([recipientId, dedupeKey])`。
- 通知只保存展示摘要和业务定位信息，不复制完整正文、图片或视频。
- 点赞和收藏不在通知范围内。
- `bizType/bizId` 跳转：`forum/postId` → 帖子详情，`task/taskId` → 任务详情，`mall/orderId` → 订单详情；`system/noticeId` 在通知列表内阅读，不跳转。
- 业务目标被删除、不存在或当前用户无权访问时，通知保留，点击提示“内容已不存在”。

## 事件矩阵

| 类型 | 触发状态/动作 | actor | recipient | bizType / bizId | dedupeKey |
| --- | --- | --- | --- | --- | --- |
| `FORUM_POST_REPLY` | 他人直接回复帖子，回复创建成功 | 回复作者 | 帖子作者 | `forum` / `postId` | `forum:reply:{replyId}:recipient:{recipientId}` |
| `FORUM_REPLY_REPLY` | 他人回复某条评论，回复创建成功 | 回复作者 | 父评论作者 | `forum` / `postId` | `forum:reply:{replyId}:recipient:{recipientId}` |
| `TASK_CLAIMED` | `PENDING_TAKE` → `IN_PROGRESS` | 接单人 | 发布者 | `task` / `taskId` | `task:{taskId}:TASK_CLAIMED:{version}:recipient:{recipientId}` |
| `TASK_ABANDONED` | `IN_PROGRESS` → `PENDING_TAKE` | 接单人 | 发布者 | `task` / `taskId` | `task:{taskId}:TASK_ABANDONED:{version}:recipient:{recipientId}` |
| `TASK_SUBMITTED` | `IN_PROGRESS` → `PENDING_CONFIRM` | 接单人 | 发布者 | `task` / `taskId` | `task:{taskId}:TASK_SUBMITTED:{version}:recipient:{recipientId}` |
| `TASK_CONFIRMED` | `PENDING_CONFIRM` → `COMPLETED` | 发布者 | 接单人 | `task` / `taskId` | `task:{taskId}:TASK_CONFIRMED:{version}:recipient:{recipientId}` |
| `TASK_REJECTED` | `PENDING_CONFIRM` → `IN_PROGRESS` | 发布者 | 接单人 | `task` / `taskId` | `task:{taskId}:TASK_REJECTED:{version}:recipient:{recipientId}` |
| `TASK_CANCELLED` | 发布者将已被领取的 `IN_PROGRESS` 或 `PENDING_CONFIRM` 任务改为 `CANCELLED` | 发布者 | 接单人 | `task` / `taskId` | `task:{taskId}:TASK_CANCELLED:{version}:recipient:{recipientId}` |
| `MALL_ORDER_CREATED` | 买家创建 `pending` 订单 | 买家 | 卖家 | `mall` / `orderId` | `mall:{orderId}:MALL_ORDER_CREATED:{version}:recipient:{recipientId}` |
| `MALL_ORDER_CANCELLED` | `pending` → `cancelled` | 发起取消的买家或卖家 | 交易另一方 | `mall` / `orderId` | `mall:{orderId}:MALL_ORDER_CANCELLED:{version}:recipient:{recipientId}` |
| `MALL_ORDER_STATUS_CHANGED` | 卖家将 `pending` → `completed` | 卖家 | 买家 | `mall` / `orderId` | `mall:{orderId}:MALL_ORDER_STATUS_CHANGED:{version}:recipient:{recipientId}` |
| `SYSTEM_NOTICE` | 超级管理员确认发布，向当时全部 `enabled = true` 用户分发 | 系统（`actorId = null`） | 每位启用用户 | `system` / `noticeId` | `system:{noticeId}`；数据库唯一键同时包含 `recipientId` |

说明：

- 任务和订单每次成功状态变化都会递增 `version`，去重键同时包含版本与接收人，避免同一业务经过相同状态名称多次时误去重。
- 论坛以新建的 `replyId` 作为事件版本，并显式包含接收人。
- 系统通知以 `clientRequestId` 作为 `noticeId` 和发布意图版本；同一接收人只能保存一次 `system:{noticeId}`。相同管理员、内容和请求标识的重试返回首次结果；不同内容或管理员复用标识返回 409。
- 发布者取消尚未被领取的 `PENDING_TAKE` 任务没有接单人，因此不生成 `TASK_CANCELLED`。

## 用户通知 API

所有接口都要求小程序 Bearer 登录态，且只操作当前用户的数据：

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| `GET` | `/api/notifications?page=1&pageSize=20` | 倒序分页查询未软删除通知，`pageSize` 最大 50。 |
| `GET` | `/api/notifications/unread-count` | 统计当前用户未读且未软删除的通知。 |
| `PATCH` | `/api/notifications/read-all` | 将当前用户全部可见未读通知标为已读。 |
| `PATCH` | `/api/notifications/{id}/read` | 幂等标记当前用户的一条通知已读；他人、已删除或不存在返回 404。 |
| `DELETE` | `/api/notifications/{id}` | 设置 `deletedAt` 软删除；他人、重复删除或不存在返回 404。 |

## 超级管理员发布 API

- `POST /api/admin/system-notices`
- 仅 `SUPERADMIN` 可调用；普通管理员即使直接访问页面或接口也会被拒绝。
- 请求体：`title`、`content`、`clientRequestId`。标题和内容按纯文本清理；发布前后台页面二次确认并防重复提交。
- 分批向当时所有启用用户写入通知，同时写入 `SystemNoticePublication` 发布意图和管理员操作日志；整个发布使用同一事务。
- 返回 `noticeId` 和 `recipientCount`。发布后当前阶段不支持撤回。

## 数据库变化与执行边界

迁移 `20260726130000_add_notification_center` 包含：

- 新表 `notifications`：接收人、触发人、事件/业务类型、业务编号、摘要、去重键、已读时间、软删除时间和创建时间。
- 新表 `system_notice_publications`：系统通知发布意图、管理员、载荷哈希、接收人数和创建时间。
- `Task.version Int @default(0)`。
- `MallOrder.version Int @default(0)`。
- `MallOrder.clientRequestId String @db.VarChar(64)` 与 `@@unique([buyerId, clientRequestId])`。
